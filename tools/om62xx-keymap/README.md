# OM62xx 矩阵表配置器

编辑键盘的键表、矩阵硬件和「按位置读取的特殊键」，生成固件直接用的头文件。单个 HTML 文件，用浏览器（Chrome / Edge）打开 `index.html` 即可，不需要联网。

打开时默认载入本工程（SE73K）的配置，是从 `main.h`、`matrix_key.c`（`scan_key()` 和 `matrixkey_scan()` 里手写的位搬移）、`matrix_key.h` 和两个键表文件还原的。

## 能做什么

- **键位**：按物理矩阵（原理图上的列 × 行）显示每个键，基础层 / Fn 层切换。点一个键，在右边选键码：
  - 标准键（可以带 Ctrl / Shift / Alt / Win 组合，只能同一侧）、只有修饰键、多媒体键、灯光键、模式 / 连接键、功能键、系统键。
  - 支持搜索，也可以点「按键录入」后直接在电脑键盘上按（单独按一下修饰键 = 只有修饰键）。
  - 空位置点「在这里加一个按键」，删掉不用的键。

  切到「键表位置」视图可以看键表 C3..C18 的 124 项分别接的是哪个物理键。
- **Mac 模式预览**：键位页顶部「系统」切到「Mac 预览」，显示键盘在 Mac 模式下实际发出的键。
  - 两种模式用的是同一套键表。Mac 模式下固件把键表里的 Alt 和 Win 对调（`key_process()`），所以键表里的 Alt 键在 Mac 上是 ⌘ Command，Win 键是 ⌥ Option；Ctrl、Shift 不变。
  - Alt+Tab、Cmd+Tab、Ctrl+Space、Cmd+Space、显示桌面这几个组合功能键在对调之后才加上，两种模式发的一样。所以 Alt+Tab 键在 Mac 上发的是 Option+Tab，不会切换程序。
  - 「锁 Win 键」只在 Win 模式下起作用。
  - 斜体 = 两种模式发的修饰键不一样；橙色框 = 在当前模式下效果不对（比如 Mac 下的 Alt+Tab、锁 Win、Menu 键，Win 下的 Cmd+Tab、显示桌面）。右边每个键都会同时写出 Win 和 Mac 模式下发的是什么。
  - 在 Mac 预览下改修饰键、按键录入都按 Mac 键名来（勾 ⌘ Command、按 Cmd+C），存进键表时自动换算成固件要的位。
- **Mac 独立键表（可选，默认关）**：勾上键位页顶部的「Mac 独立键表」，Mac 模式就用单独的一套键表（基础层 + Fn 层），想让 Mac 下某些键和 Win 不一样时用。
  - 打开时从当前 Win 键表换算一份：Alt / Win 已经对调好，所以不改的话 Mac 下的效果和原来完全一样。之后「系统」切到「Mac 键表」就是在改这套表，修饰键直接按 Mac 写（⌘ Command、⌥ Option），不再换算。
  - 固件里 Mac 模式不再对调 Alt / Win，切换 Win / Mac 时换表。Mac 键表存在 Flash 第 8、12 页（原来就预留了），恢复出厂也会擦。
  - 检查会提示 Mac 键表里有没有切回 Win 的键（Win 模式 / Win/Mac 切换），没有的话切到 Mac 就回不去了。
  - 改了 Mac 键表还想重来，点提示条里的「从 Win 键表重新复制」（可以撤销）。关掉开关后 Mac 键表还保留，再打开还在。
- **矩阵硬件**：
  - 列线：每一列选 GPIO 直连，或者扩展列的第几步（PA7、PA6、PA4…，由 PA5 控制，翻转 KEY_EX 换列），也可以设成不用、删掉或加新列。
  - 行线：8 根，每根可以换脚或不用，引脚不连续也行。
  - 指示灯：LED 供电脚（现在是 P23）可以换脚或去掉；Num / Caps / 低电三个灯可以和列线复用，也可以接独立的脚，点亮电平可选。
- **特殊键位置**：固件里有些键不走键表，而是直接按位置读：
  - FCC 测试（`rf_fcc.c`）：进入测试的 Fn、切换频点、蓝牙 / 2.4G 模式键，以及测试中的 4 个方向键。
  - WASD 互换（`std_decode_callback()`）：W A S D 和 ↑ ← ↓ →。

  每个都可以「点选」到任意键，或者按键码自动定位（比如 Fn 自动找到键表里 Fn 所在的位置）。
- **导入引脚配置**（「矩阵硬件」页）：把引脚配置器「导出配置」得到的 JSON 导入进来（顶部「导入配置」里直接粘也认），就按引脚配置器的实际配置检查，下拉框里也显示每个脚的实际用途；没导入时只按 SE73K 默认用途提示。导入的配置只用来检查，不会改这边的设置；改了引脚配置要重新导入。
- **检查**：
  - 引脚冲突、扩展步重复、行列没接脚导致扫不到的键。
  - 指示灯和列线复用的电平问题。
  - 键表里有键码但按不到的位置、两个物理键共用一项。
  - 固件没实现的特殊键、左右修饰键混用、Fn 层用不了。
  - 特殊键位置上的键和用途对不上。
- **生成代码**：
  - `matrix_cfg.h`：引脚、物理位置到键表的映射、特殊键位置、指示灯读写宏。
  - `matrix_key_tbl_win.h`、`matrix_key_tbl_win_fn.h`：键表，格式和原来一样，每行注释标出是哪个物理键。
  - 打开 Mac 独立键表时还有 `matrix_key_tbl_mac.h`、`matrix_key_tbl_mac_fn.h`。
- **其他**：
  - 导入已有的键表 `.h`，按数组名自动判断是哪一层。
  - JSON 导入导出，撤销（Ctrl+Z）。
  - 配置保存在浏览器本地，换电脑请用导出 / 导入。

## 同步到工程（推荐）

点右上角「同步到工程」，生成的文件直接写进工程，不用复制粘贴：

1. **第一次**会让你选工程文件夹：选仓库根目录（里面有 `projects/mouse_demo`），或者直接选 `projects/mouse_demo`。浏览器会记住它，以后再点只会问一次是否允许写入。
2. 弹出的对话框列出每个文件是**新建 / 有改动 / 不变**；「检查」里还有错误时也会提示。点「写入 N 个文件」只写有改动的那些。
3. 配置本身也会存进工程的 `config/keymap_config.json`，可以和代码一起提交。换电脑或者别人改过时，对话框里会出现「从工程载入配置」。
4. 同步时会先读工程里的 `config/io_config.json`（引脚配置器同步进去的），按它检查两边的引脚设置，不用再手动导入引脚配置。
5. 键表有改动时，写完会提醒：烧录后要长按 Fn+Esc 2 秒恢复出厂。

需要用 **Chrome 或 Edge** 打开工程里的 `index.html`（本地文件）。Firefox、Safari 和 claude.ai 上的在线版不能直接写本地文件，只能在「生成代码」页复制或下载。

## 接进工程（手动也是这几步）

1. `matrix_cfg.h` → `projects/mouse_demo/config/`；键表（两个，打开 Mac 独立键表时四个）→ `projects/mouse_demo/periph/`。用 UTF-8 保存，覆盖原文件，重新编译。Mac 独立键表的开关是 `matrix_cfg.h` 里的 `MATRIX_MAC_KEYMAP`，不用改别的代码。
2. **键表存在 Flash 里**：固件只在 Flash 里没有键表时才从代码复制，所以烧录后要长按 **Fn + Esc** 2 秒恢复出厂，新键表才生效。
3. 改了行列或指示灯的引脚，还要到引脚配置器（`tools/om6239-io-config`）里同步改，重新生成 `io_config.h` / `io_config.c`。两边靠下面这些设置认出同一个脚：

   | 矩阵这边 | 引脚配置器里要设成 |
   |---|---|
   | 行线 | 「矩阵行」，开上拉，下降沿唤醒 |
   | 直连列（含和列线复用的指示灯） | 「矩阵列」，开上拉 |
   | 扩展列控制脚 | 「GPIO 输出」，标签 `KEY_EX` |
   | LED 供电脚 | 「GPIO 输出」，标签 `LED_VDD`，初始电平 = 关电 |
   | 独立接线的指示灯 | 「GPIO 输出」，标签 `LED_NUM` / `LED_CAPS` / `LED_LOW`，初始电平 = 灭灯 |

   - 在这边导入引脚配置的 JSON，「检查」里会直接列出对不上的地方。
   - **两边对不上时编译也会报错**（`periph/matrix_key.c` 开头的检查），错误信息会说是哪一项、该去哪个配置器改。
   - 休眠和深度休眠时的引脚状态不用手改：`main.c` 的 `mouse_periph_wakeup_enable()` 和 `drv_pmu.c` 的深度休眠，都是用 `io_config.h` 的上电寄存器值，去掉 `matrix_cfg.h` 里直连列的上拉位（`MATRIX_DIRECT_PU_MASK`），再按 `MATRIX_SLEEP_LOW_MASK` / `MATRIX_SLEEP_HIGH_MASK` 把列线、KEY_EX、LED 供电设成固定电平。

## 固件怎么用这些配置

`periph/matrix_key.c`：

1. `scan_key()`：
   - 依次拉低 `MATRIX_DIRECT_PINS` 里的直连列，用 `MATRIX_ROW_GATHER()` 读行线。
   - 再翻转 `MATRIX_EX_NUM` 次 KEY_EX 读扩展列。
   - 结果按扫描顺序存进 `matrix_raw[]`。
2. `matrixkey_scan()`：
   - 在 `matrix_raw[]` 上做鬼键检测。
   - `matrix_pack()` 按 `MATRIX_SLOT_MAP` 把每个物理位置换成键表位置，写进 `matrix_status[3..18]`。
   - 之后的键表解码和原来一样。

`periph/matrix_key.h` 用 `KEYPOS_xxx` 换算出原来的 `iKEY_FN_C`、`iKEY_INDEX_W` 等宏，`rf_fcc.c` 和 `userdefined_key_callback.c` 不用改。没指定的位置是 `MATRIX_POS_NONE`，永远读不到按下。

`main/main.h` 里的 `MATRX_ALL_*`、`KEY_EX_*`、`mLED_*` 也都从 `matrix_cfg.h` 展开，换脚不用改代码。

Win / Mac（`MATRIX_MAC_KEYMAP`）：

- 0（默认）：两种模式共用 `matrix_key_tbl_win*.h`，`key_process()` 在 Mac 模式下把 Alt 和 Win 对调。Mac 键表不编进固件。
- 1：`flash/flash_process.c` 的 `laod_key_cfg()` 在 Mac 模式下加载 `matrix_key_tbl_mac*.h`（Flash 第 8、12 页），`key_process()` 不再对调。按键切换 Win / Mac、或者开机按通道读到的模式和原来不同时（`win_mac_load()`），都会重新加载键表。
- 两种设置下，默认配置的 Mac 模式发出的键完全一样（主机上逐项核对过）。

## 验证

用配置器生成的默认配置和原来的代码做过对比（主机上编译运行）：

- 20 列 × 8 行每个单键，加 200 万组随机按键组合：查表结果和原来 `matrixkey_scan()` 手写搬移的 `matrix_status[3..18]` 完全一致。
- 行线读取：`MATRIX_ROW_GATHER()` 和原来 `(~DATA>>4)&0xFF` 一致。另外测了不连续的行线。
- 生成的两个键表和原来的逐字节相同，特殊键位置和原来的宏数值相同。
- 整个工程用 clang（Cortex-M0）编译检查，未解析符号和改动前一致。改过配置（P23 改成列、去掉 LED 供电脚、行线不连续、加列、不用扩展列）后也能编译。

尚未在 Keil 里编译或上板运行。

唯一的行为差别：检测到鬼键的那一帧，原来 `matrix_status[]` 里留的是没搬移的原始值，现在保持上一帧的结果。这个值只有 FCC 测试会在这一帧读到。

## 现有配置里发现的问题

- **FCC 测试的键位置（已改正）**：
  - 原来的宏指向旧布局：Fn 指到 C8 R7（N 键），蓝牙模式键指到 Esc，2.4G 模式键指到逗号，「右 / 左 / 上」三个测试键指到 ScrollLock、计算器、O。
  - 现在按键码定位：Fn = C9 R7，蓝牙模式键 = 蓝牙 1（C4 R4），右 / 左 / 上 / 下 = 方向键。
  - 2.4G 模式下要按的键：键表里没有 2.4G 模式键（模式由拨动开关选），定为配对键的位置 C7 R0（基础层 Tab，Fn 层配对），也就是 2.4G 下用来配对的键。
  - 进入测试的组合：连接 / 配对过程中，同时按住 Fn + ↓ + 蓝牙 1（蓝牙模式）或 Fn + ↓ + Tab（2.4G 模式）。这几个键不在同一列，不会被当成鬼键。
- **C17 R6 按不到**：键表里这一项是「静音」，但原来的搬移代码把物理 C17 R6 丢掉了，也没有别的键接到这里。
